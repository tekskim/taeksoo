# TDS Page Plan

Figma 파일을 크롤링하여 내부 프레임 목록을 자동 추출하고, TDS 라우트와 매핑하여 페이지별 구현 계획을 생성하는 스킬입니다.

## 트리거

- "페이지 플랜", "page plan", "Figma 분석", "Figma 크롤링"
- "페이지 계획 세워줘", "Figma에서 페이지 뽑아줘"
- 오케스트레이터(`tds-page-sync`)에서 Phase 0/1로 자동 호출

## 입력

- **Figma URL**: 파일 URL 또는 특정 프레임 URL
  - 파일 URL: `https://figma.com/design/{fileKey}/{fileName}` → 전체 크롤링
  - 프레임 URL: `https://figma.com/design/{fileKey}/{fileName}?node-id={nodeId}` → 해당 프레임만

## 출력

- **figma-page-map.md**: `.cursor/skills/tds-page-sync/figma-page-map.md`
- **계획서 파일**: `.cursor/skills/tds-page-sync/specs/pages/{PageName}-plan.md` (페이지별)

## 동작 절차

### Step 1: Figma URL 파싱

URL에서 `fileKey`와 `nodeId`를 추출합니다.

```
https://figma.com/design/AbCdEf/MyFile?node-id=1-2
→ fileKey: "AbCdEf", nodeId: "1:2"

https://figma.com/design/AbCdEf/MyFile
→ fileKey: "AbCdEf", nodeId: 없음 (전체 크롤링)
```

**브랜치 URL 처리**:

```
https://figma.com/design/{fileKey}/branch/{branchKey}/{fileName}
→ fileKey로 branchKey를 사용
```

### Step 2: Figma 파일 구조 크롤링

`get_metadata` MCP 도구로 파일의 전체 구조를 가져옵니다.

```
CallMcpTool:
  server: "user-Figma"
  toolName: "get_metadata"
  arguments:
    fileKey: "{fileKey}"
    nodeId: "0:1"  # 루트 페이지 (전체 파일 구조)
    clientLanguages: "typescript"
    clientFrameworks: "react"
```

**nodeId가 지정된 경우**: 해당 노드와 그 자식 노드만 크롤링합니다.

반환된 XML에서 프레임 목록을 추출합니다:

- `type="FRAME"` 또는 `type="SECTION"` 노드를 수집
- 각 노드의 `name`, `id`, `width`, `height` 기록
- 중첩된 경우 최상위 프레임만 수집 (페이지 단위)

### Step 3: 프레임 이름 파싱 및 분류

Figma 프레임 이름에서 페이지 정보를 파싱합니다.

**일반적인 네이밍 패턴**:

| Figma 프레임 이름    | 파싱 결과                        |
| -------------------- | -------------------------------- |
| `Workloads - List`   | service: Workloads, type: List   |
| `Workloads - Detail` | service: Workloads, type: Detail |
| `Models / Create`    | service: Models, type: Create    |
| `Dashboard`          | service: Dashboard, type: Main   |
| `Settings`           | service: Settings, type: Main    |

**분류 기준**:

- **List**: 테이블 + 필터 + 페이지네이션이 있는 목록 페이지
- **Detail**: 상세 정보 + 탭이 있는 상세 페이지
- **Create**: 폼이 있는 생성/편집 페이지
- **Main**: 대시보드, 설정 등 단독 페이지

파싱이 애매한 경우 원본 이름을 그대로 사용하고, 사용자 확인을 요청합니다.

### Step 4: TDS 라우트 매핑

파싱된 페이지를 기존 TDS 라우트와 매핑합니다.

**매핑 소스**:

1. `src/App.tsx`에서 AI Platform 라우트 목록 추출
2. `src/pages/ai-platform/` 디렉토리에서 기존 페이지 파일 확인
3. `src/components/AIPlatformSidebar.tsx`에서 사이드바 메뉴 구조 확인

**매핑 규칙**:

- 프레임 이름의 service 부분을 kebab-case로 변환 → 라우트 경로
- 기존 파일이 있으면 해당 파일에 매핑, 없으면 신규 생성 표시
- Detail 페이지는 `/:id` 파라미터 추가

```
Workloads - List → /ai-platform/workloads → WorkloadsPage.tsx (기존)
Workloads - Detail → /ai-platform/workloads/:id → WorkloadDetailPage.tsx (기존)
New Service → /ai-platform/new-service → NewServicePage.tsx (신규)
```

### Step 5: figma-page-map.md 생성

매핑 결과를 `.cursor/skills/tds-page-sync/figma-page-map.md`에 저장합니다.

```markdown
# Figma Page Map

> Auto-generated by tds-page-plan
> Figma File: {fileKey}
> Generated: {timestamp}

## Pages

| #   | Figma Frame        | nodeId | Type   | TDS Route                  | Page File              | Existing | Status  |
| --- | ------------------ | ------ | ------ | -------------------------- | ---------------------- | -------- | ------- |
| 1   | Dashboard          | 100:1  | Main   | /ai-platform               | AIPlatformPage.tsx     | yes      | pending |
| 2   | Workloads - List   | 100:2  | List   | /ai-platform/workloads     | WorkloadsPage.tsx      | yes      | pending |
| 3   | Workloads - Detail | 100:3  | Detail | /ai-platform/workloads/:id | WorkloadDetailPage.tsx | yes      | pending |
| 4   | New Feature        | 100:4  | List   | /ai-platform/new-feature   | NewFeaturePage.tsx     | no       | pending |

## Unmapped Frames

프레임이 있지만 매핑하지 못한 항목:

| Figma Frame | nodeId | Reason                      |
| ----------- | ------ | --------------------------- |
| Icon Set    | 200:1  | 아이콘 에셋 (페이지 아님)   |
| Color Guide | 200:2  | 디자인 가이드 (페이지 아님) |
```

### Step 6: 사용자 매핑 확인

생성된 `figma-page-map.md`를 사용자에게 보여주고 확인합니다.

- "전체 승인" → Step 7로
- "일부 제외" → 해당 항목 제거 후 진행
- "매핑 수정" → 수정 후 재확인
- "추가" → 누락된 프레임 추가

### Step 7: 페이지별 계획서 생성

승인된 각 페이지에 대해 `get_design_context`를 호출하여 계획서를 생성합니다.

```
CallMcpTool:
  server: "user-Figma"
  toolName: "get_design_context"
  arguments:
    fileKey: "{fileKey}"
    nodeId: "{nodeId}"
    clientLanguages: "typescript"
    clientFrameworks: "react"
```

반환된 코드와 스크린샷을 분석하여 계획서를 작성합니다.

**계획서 형식** (`specs/pages/{PageName}-plan.md`):

````markdown
# {PageName} Page Plan

> Figma Frame: {frameName}
> nodeId: {nodeId}
> Type: {List|Detail|Create|Main}
> Target: src/pages/ai-platform/{PageName}Page.tsx

## Layout Structure

- PageShell (AIPlatformSidebar, TabBar, TopBar)
- PageHeader: title="{title}", actions=[{buttons}]
- {추가 레이아웃 요소}

## Components

| #   | Component         | TDS Import        | Props                     | Notes           |
| --- | ----------------- | ----------------- | ------------------------- | --------------- |
| 1   | PageHeader        | PageHeader        | title, actions            | 표준 패턴       |
| 2   | Table             | Table             | columns, data, selectable | {컬럼수}개 컬럼 |
| 3   | FilterSearchInput | FilterSearchInput | filters, appliedFilters   | {필터수}개 필터 |
| 4   | Pagination        | Pagination        | currentPage, totalPages   | 표준 패턴       |

## Table Columns (List 페이지인 경우)

| #   | Header  | Key       | Align  | Width | Sortable | Render          |
| --- | ------- | --------- | ------ | ----- | -------- | --------------- |
| 1   | Name    | name      | left   | 200px | yes      | text + link     |
| 2   | Status  | status    | center | 80px  | yes      | StatusIndicator |
| 3   | Created | createdAt | right  | 150px | yes      | date            |

## Mock Data Shape

```typescript
interface {PageName}Item {
  id: string;
  name: string;
  status: 'active' | 'error' | 'building' | 'muted';
  // ...
}
```
````

## States

- **Default**: 데이터가 있는 상태
- **Empty**: EmptyState 표시 (아이콘, 메시지, CTA 버튼)
- **Loading**: (필요 시)

## Estimated Effort

- Size: S / M / L
- Reason: {사유}

````

### Step 8: 요약 리포트 출력

모든 계획서 생성 후 요약을 출력합니다.

```markdown
## Page Plan Summary

| # | Page | Type | Effort | Components | Status |
|---|---|---|---|---|---|
| 1 | Dashboard | Main | L | 12 | ready |
| 2 | Workloads | List | M | 8 | ready |
| 3 | Models | List | M | 7 | ready |

Total: {N} pages, Est. effort: {S}x{n} + {M}x{n} + {L}x{n}
````

## 주의사항

- `get_metadata`는 구조만 반환하고 디자인 상세는 없음 → 계획서 생성 시 `get_design_context` 필수
- Figma API rate limit 주의 → `get_design_context`는 페이지당 1회만 호출, 결과 캐시
- 프레임 이름이 모호한 경우 사용자에게 확인 요청
- 기존 페이지가 있는 경우 "수정" vs "전체 교체" 여부를 사용자에게 확인
- 매핑 결과는 `figma-page-map.md`에 저장하여 후속 스킬들이 참조
